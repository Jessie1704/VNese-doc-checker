# B.2. Code base sẵn có, codekb đã cũ {#c-b2}

> **Lưu ý:** Đây là minh hoạ dựng theo tài liệu, không phải bản ghi của một lần chạy thật. Trình tự stage và dạng output dựng theo tài liệu chính thức của công cụ. Các con số, tên file và nội dung chỉ là ví dụ.

Minh hoạ tình huống thường gặp nhất ở dự án đã có code: chạy lần thứ hai, codekb từ lần trước không còn khớp với code thật.

Cần chú ý: rerun guard phát hiện điều này, và bạn phải chọn giữa full rescan và focused rescan.

## Bối cảnh

```
$ ls
checkout-api/ package.json src/ tests/ .git/

$ git log --oneline -3
a3f8c21 thêm luồng hoàn tiền
7b21e04 sửa lỗi làm tròn thuế
c9d4e17 nâng phiên bản thư viện thanh toán
```

Repo này dùng git, là điều kiện bắt buộc để rerun guard hoạt động.

```
$ bun .claude/tools/aidlc-utility.ts detect --json
{
  "projectType": "Brownfield",
  "languages": ["TypeScript"],
  "frameworks": ["Express"],
  "buildSystem": "npm",
  "submodules": []
}
```

> **Ghi chú:** Nếu `git status` báo thư mục không phải repo git, dừng lại và chạy `git init` trước. Xem [11](#c-11), phần về kết quả `UNVERIFIED`.

## Bắt đầu

```
> /aidlc feature Thêm thông báo cho giao dịch hoàn tiền

─── Scope Detection ─────────────────────────────────────────────
Detected scope: feature (Standard depth, Standard test strategy)
▸ Approve scope? [Yes / Change scope / Change depth / Change test strategy]
> Yes

$ grep -i "project type" aidlc/spaces/default/intents/260922-thong-bao/aidlc-state.md
**Project Type**: Brownfield
```

Đúng như mong đợi. Stage phân tích code sẽ execute.

## Rerun guard phát hiện codekb đã cũ

```
[AIDLC] INCEPTION > Reverse Engineering [░░░░░░░░░] 0/9 -- developer ctx:88%

Kiểm tra codekb hiện có trước khi quét...

$ bun .claude/tools/aidlc-utility.ts codekb-scope-diff --repo checkout-api
{
  "verdict": "STALE",
  "store_scope": { "kind": "full", "paths": ["./"] },
  "changed_paths": [
    "src/payments/refund.ts",
    "src/payments/tax.ts",
    "package.json"
  ]
}
```

Kết quả `STALE`: các đường dẫn đã từng được phân tích đã thay đổi kể từ lần quét trước. Ba file trong danh sách khớp với ba commit gần nhất.

> **Ghi chú:** Nếu repo này không dùng git, kết quả sẽ là `UNVERIFIED` thay vì `STALE`, và bạn sẽ không biết codekb còn đúng hay không.

## Chọn kiểu quét

```
▸ Codekb cho checkout-api đã cũ. Bạn muốn làm gì?
  (1) Quét lại toàn bộ — thay thế codekb hiện có
  (2) Quét lại theo phạm vi hẹp — chỉ định đường dẫn, gộp vào codekb
  (3) Dùng lại codekb hiện có — chấp nhận rủi ro
> 2

▸ Phạm vi cần quét lại:
> src/payments/
```

Chọn focused rescan vì thay đổi nằm gọn trong một phần, và phần còn lại của codekb vẫn đúng.

```
Quét hẹp: src/payments/
Giữ lại phần diễn giải đã có cho các phần không đổi.

  ✓ bước 1 — quét code (developer)
  ✓ bước 2 — tổng hợp (architect)

Đã gộp vào codekb: aidlc/spaces/default/codekb/checkout-api/
```

> **Lưu ý:** Focused rescan gộp thêm vào codekb cũ và giữ lại phần diễn giải đã có. Vì vậy codekb giờ có hai lớp chất lượng: phần vừa quét lại là mới, phần còn lại là cũ và chưa được kiểm tra lại. Khi nghi ngờ, chọn full rescan.

```

Đây là cách dùng đúng lựa chọn thứ hai. Artifact này là đầu vào của năm stage khác; sửa ở đây rẻ hơn sửa ở năm chỗ.

## Stage `practices-discovery`: lấy từ những gì quan sát được

```
[AIDLC] INCEPTION > Practices Discovery [▓░░░░░░░░] 1/9 -- pipeline-deploy ctx:71%

  - Nhánh đặt tên theo <loại>/<mô-tả-ngắn>

## Nếu kết quả là `UNVERIFIED`

Trường hợp thư mục không dùng git:

```
$ bun .claude/tools/aidlc-utility.ts codekb-scope-diff --repo checkout-api
{
  "verdict": "UNVERIFIED",
  "reason": "not a git work tree — no computable fingerprint"
}
```

Không có fingerprint thì không biết codekb còn đúng hay không, và mọi lần chạy sau đều là đoán. Cách xử lý: chạy `git init`, commit một lần, rồi full rescan.
