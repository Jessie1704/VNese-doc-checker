# A.1. Ma trận stage × profile {#c-a1}

Bảng này tách hai cơ chế rất dễ bị nhầm với nhau:

| Cột | Ý nghĩa | Quyết định lúc nào |
| --- | --- | --- |
| Trên route | Stage có tên trong `scopes:` của profile | Lúc bạn chọn profile |
| Điều kiện execute | Lúc chạy, stage chạy thật hay tự bỏ qua | Lúc chạy, theo `condition:` |

Stage trên route vẫn có thể không execute; khi đó nó ghi một receipt `skipped` vào audit. Điều này khác với stage nằm ngoài route.

## Điều kiện execute

Cột `condition:` giữ nguyên văn tiếng Anh từ định nghĩa stage của công cụ; dấu "..." là chỗ công cụ tự rút gọn.

| Stage | `execution:` | `condition:` |
| --- | --- | --- |
| `state-init` | ALWAYS | Creates full populated state file and determines routing — auto-proceeds |
| `workspace-detection` | ALWAYS | Scans and classifies workspace — auto-proceeds (no approval gate) |
| `workspace-scaffold` | ALWAYS | Ensure-exists the per-intent record and in-scope phase dirs, idempotent (creates on demand, skips existing) |
| `approval-handoff` | ALWAYS | Always executes — compiles all Ideation artifacts into initiative brief for approval |
| `feasibility` | CONDITIONAL | Execute when there are integration constraints, regulatory requirements, or significant technical uncertainty. Skip for trivial changes with no technical risk. |
| `intent-capture` | ALWAYS | First stage of every workflow — establishes the initiative's foundation |
| `market-research` | CONDITIONAL | Execute when initiative has external market positioning or build-vs-buy considerations. Skip for internal tools, bug fixes, or refactors. |
| `rough-mockups` | CONDITIONAL | Execute when user-facing UI is part of the initiative; for API/backend, produce system interaction diagrams. Skip for non-UI, API-only, or infrastructure-onl... |
| `scope-definition` | ALWAYS | Always executes — defines the scope boundary and prioritized backlog |
| `team-formation` | CONDITIONAL | Execute when team composition, capacity, or mob planning is relevant. Skip for solo developer or small team projects. |
| `contract-design` | CONDITIONAL | Execute when the system has any formal contract to pin down — an inter-unit boundary (more than one unit that must integrate) OR a unit that exposes a public... |
| `delivery-planning` | ALWAYS | Always executes — capstone Inception stage, produces the detailed execution plan for Construction and Operation |
| `domain-design` | CONDITIONAL | Execute when new components or logical building blocks are needed. Skip when changes are modifications to existing components only. |
| `practices-discovery` | CONDITIONAL | Always rerun for freshness. Brownfield discovers from evidence + reverse-engineering artifacts. Greenfield prompts user via structured questions using org.md... |
| `refined-mockups` | CONDITIONAL | Execute when user-facing UI exists and rough mockups were produced in Ideation; for APIs, refine interaction diagrams |
| `requirements-analysis` | ALWAYS | Always executes — depth scales with project complexity |

| `user-stories` | CONDITIONAL | Execute when user-facing features, multiple personas, complex business logic, or cross-team work is involved. Skip for pure refactoring, isolated bug fixes, ... |
